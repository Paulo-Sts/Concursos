# Banco de Dados - Linguagem SQL 4

## 1. Inner Join
- O comando `INNER JOIN` é utilizado para combinar registros de duas ou mais tabelas em um banco de dados.
- Ele retorna apenas as linhas onde há uma correspondência entre as colunas especificadas na condição de junção (ON) em ambas as tabelas.
- Funciona como uma interseção entre os conjuntos de dados das tabelas envolvidas.
- Exemplo: Para selecionar o nome dos produtos e suas respectivas categorias, utiliza-se a seguinte consulta:
```sql
SELECT p.nome_prod AS produto, c.nome_categoria AS categoria
FROM produto AS p
INNER JOIN categoria AS c ON (p.id_categoria = c.id_categoria);
```

### 1.1 Produto
| NOME_PROD | ID_CATEGORIA | PRECO_PROD | UND_PROD |
|-----------|--------------|------------|----------|
| Café      | 10           | R$ 8,99    | KG       |
| Açúcar    | 10           | R$ 10,20   | KG       |
| Sabão em Pó | 20         | R$ 9,90    | KG       |
| Vinho     | 30           | R$ 59,99   | 750 ML   |
| Refrigerante |           | R$ 7,90    | 2 L      |

### 1.2 Categoria
| ID_CATEGORIA | NOME_CATEGORIA |
|--------------|----------------|
| 10           | Mercearia      |
| 20           | Limpeza        |
| 30           | Bebida         |
| 40           | Açougue        |

### 1.3 Resultado do Inner Join
| PRODUTO | CATEGORIA |
|---------|-----------|
| Café    | Mercearia |
| Açúcar  | Mercearia |
| Sabão em Pó | Limpeza |
| Vinho   | Bebida    |

> [!CAUTION] OBSERVAÇÃO:
> - O produto "Refrigerante" não aparece no resultado do `INNER JOIN` porque não possui um `id_categoria` correspondente na tabela Categoria.
> - O `INNER JOIN` compara dois conjuntos e realiza a sua interseção, trazendo de volta tudo aquilo que pertence tanto à tabela Produto (P) quanto à tabela Categoria (C).
> - O `JOIN` é uma operação otimizada. Embora teoricamente faça um cruzamento de dados, os bancos de dados utilizam estruturas como índices para realizar a operação de forma mais rápida, sem a necessidade de cruzamentos desnecessários.

## 2. Left Outer Join
- O comando `LEFT OUTER JOIN` (ou simplesmente `LEFT JOIN`) retorna todos os registros da tabela à esquerda (primeira tabela mencionada) e os registros correspondentes da tabela à direita.
- Se não houver correspondência, os campos da tabela à direita serão preenchidos com `NULL`.
- É chamado de "externo" porque, além da interseção, inclui todos os elementos que pertencem apenas ao conjunto da esquerda.
- Exemplo:
```sql
SELECT p.nome_prod AS produto, c.nome_categoria AS categoria
FROM produto AS p
LEFT OUTER JOIN categoria AS c ON (p.id_categoria = c.id_categoria);
```

### 2.1 Resultado do Left Outer Join
| PRODUTO | CATEGORIA |
|---------|-----------|
| Café    | Mercearia |
| Açúcar  | Mercearia |
| Sabão em Pó | Limpeza |
| Vinho   | Bebida    |
| Refrigerante | null |

> [!CAUTION] OBSERVAÇÃO:
> - O "Left Outer Join" indica a ordem em que a informação é trazida. Quer-se todos os elementos da interseção de P e C, juntamente com todos os elementos que pertencem apenas a P.
> - Percebe-se a presença de "Refrigerante", mesmo que esse não possua categoria.
> - Em contrapartida, a categoria "Açougue" não aparece, uma vez que se encontra no outro grupo, que não é abrangido pelo comando `LEFT OUTER JOIN`.
> - Alguns bancos de dados permitem o uso do comando `LEFT JOIN`, que realiza a mesma função.

## 3. Right Outer Join
- O comando `RIGHT OUTER JOIN` (ou `RIGHT JOIN`) retorna todos os registros da tabela à direita (segunda tabela mencionada) e os registros correspondentes da tabela à esquerda.
- Se não houver correspondência, os campos da tabela à esquerda serão preenchidos com `NULL`.
- É o oposto lógico do `LEFT OUTER JOIN`, incluindo todos os elementos que pertencem apenas ao conjunto da direita.
- Exemplo:
```sql
SELECT p.nome_prod AS produto, c.nome_categoria AS categoria
FROM produto AS p
RIGHT OUTER JOIN categoria AS c ON (p.id_categoria = c.id_categoria);
```

### 3.1 Resultado do Right Outer Join
| PRODUTO | CATEGORIA |
|---------|-----------|
| Café    | Mercearia |
| Açúcar  | Mercearia |
| Sabão em Pó | Limpeza |
| Vinho   | Bebida    |
| null    | Açougue   |

> [!CAUTION] OBSERVAÇÃO:
> - Em contrapartida ao `LEFT OUTER JOIN`, o `RIGHT OUTER JOIN` faz com que sejam retornados todos os elementos da interseção de P e C, com os elementos presentes no conjunto C.
> - Para qualquer tipo de `JOIN`, deve-se listar as tabelas, colocar o alias (apelido) e o comando `JOIN`. Ao final, coloca-se o `ON`, que será o responsável por realizar a comparação das chaves.
> - As comparações de conjunto só podem existir caso uma tabela esteja relacionada com a outra de alguma forma.

## 4. Full Outer Join
- O comando `FULL OUTER JOIN` combina os resultados do `LEFT OUTER JOIN` e do `RIGHT OUTER JOIN`.
- Ele retorna todas as linhas de ambas as tabelas, preenchendo com `NULL` onde não houver correspondência.
- Inclui a interseção, os elementos apenas da esquerda e os elementos apenas da direita.
- Exemplo:
```sql
SELECT p.nome_prod AS produto, c.nome_categoria AS categoria
FROM produto AS p
FULL OUTER JOIN categoria AS c ON (p.id_categoria = c.id_categoria);
```

### 4.1 Resultado do Full Outer Join
| PRODUTO | CATEGORIA |
|---------|-----------|
| Café    | Mercearia |
| Açúcar  | Mercearia |
| Sabão em Pó | Limpeza |
| Vinho   | Bebida    |
| null    | Açougue   |
| Refrigerante | null |

> [!CAUTION] OBSERVAÇÃO:
> - O `FULL OUTER JOIN` irá realizar a união do `LEFT OUTER JOIN` e do `RIGHT OUTER JOIN`. Dessa forma, aparecerá tanto os elementos presentes em ambos os campos quanto aqueles presentes em apenas um.

## 5. Inner Join – Auto Relacionamento
- O auto relacionamento, ou `self join`, é um tipo de `INNER JOIN` onde uma tabela é unida a si mesma.
- Isso é útil quando a tabela contém uma referência para seus próprios registros, como um campo que indica o chefe de um funcionário.
- A tabela recebe dois alias diferentes para que possa ser referenciada como duas tabelas distintas na consulta.
- Exemplo: Para listar o nome de cada empregado e o nome de seu respectivo chefe, utiliza-se a seguinte consulta:
```sql
SELECT E.nome AS Empregado, C.nome AS Chefe
FROM Empregado AS E
INNER JOIN Empregado AS C ON (E.id_chefe = C.id_emp);
```
