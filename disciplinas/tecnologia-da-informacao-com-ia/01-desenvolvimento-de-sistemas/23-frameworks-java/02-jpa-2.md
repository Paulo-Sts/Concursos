# Persistência com JPA e Hibernate 2

## 1. Relacionamentos entre Entidades JPA
- Os relacionamentos no JPA são fundamentais para estruturar entidades no banco de dados.
- Existem quatro tipos principais de relacionamentos:
  - Um para um (@OneToOne);
  - Um para muitos (@OneToMany);
  - Muitos para um (@ManyToOne);
  - Muitos para muitos (@ManyToMany).
- Relacionamentos podem ser unidirecionais ou bidirecionais.
- A anotação @JoinColumn especifica a coluna da chave estrangeira que conecta a entidade referenciada.
- As operações em cascata (cascade) permitem propagar ações de persistência de uma entidade para suas associadas.

### 1.1 Relacionamento @OneToOne
- Ocorre quando uma entidade A está associada a uma única instância da entidade B, e vice-versa.
- Utilizado quando uma entidade possui detalhes complementares em outra.
- Exemplo clássico: relação entre pessoa e endereço (cada pessoa possui um endereço, e cada endereço pertence a uma única pessoa).
- A anotação @OneToOne estabelece essa relação no JPA.
- A anotação @JoinColumn especifica a coluna da chave estrangeira.
- Operações de persistência da entidade A são propagadas para a entidade B.
  - Exemplo: ao remover uma pessoa, o sistema deve remover o endereço associado para evitar inconsistência no banco de dados.

> [!CAUTION] OBSERVAÇÃO:
> - A ausência de operações em cascata pode gerar dados órfãos no banco de dados.

### 1.2 Relacionamento @OneToMany e @ManyToOne
- No relacionamento um para muitos, uma entidade A pode estar associada a muitas instâncias da entidade B.
- Em contrapartida, muitas instâncias da entidade B estão associadas a uma única instância da entidade A.
- Exemplo: um departamento pode ter muitos funcionários, mas cada funcionário pertence a apenas um departamento.
- A chave estrangeira é armazenada na tabela da entidade B (lado muitos), referenciando a entidade A.
- O relacionamento é bidirecional:
  - Em Departamento, é possível obter os funcionários;
  - Em Funcionário, é possível obter o departamento.
- Anotação @ManyToOne é utilizada no lado muitos.
- A chave estrangeira é especificada através da anotação @JoinColumn.
- Operações em cascata se aplicam: ao apagar um departamento, todos os funcionários associados devem ser removidos.

> [!TIP] DICAS:
> - mappedBy é usado no lado que não possui a chave estrangeira (lado um) para indicar o atributo que mapeia o relacionamento no lado muitos.
> - O fetch padrão para @OneToMany é LAZY (carregamento preguiçoso).

### 1.3 Relacionamento @ManyToMany
- Relacionamento mais complexo, onde uma entidade A pode estar associada a várias instâncias da entidade B e vice-versa.
- Exemplo clássico: relação entre médicos e pacientes (um paciente pode ser atendido por vários médicos e um médico pode atender vários pacientes).
- Exige uma tabela intermediária (tabela de relação) que contém as chaves estrangeiras de ambas as entidades.
- A tabela intermediária armazena as chaves estrangeiras referentes às duas entidades.
- No JPA, utiliza-se a anotação @ManyToMany em ambas as entidades.
- A tabela intermediária não precisa ser uma entidade própria, mas pode ser mapeada se necessário.
- Exemplo prático: relação entre estudantes e cursos (um estudante pode estar matriculado em vários cursos e um curso pode ter vários estudantes).
- Mapeamento envolve três tabelas:
  - Tabela de estudantes;
  - Tabela de cursos;
  - Tabela intermediária (exemplo: "estudante_curso").
- Utiliza-se o conceito de "join table" no JPA para configurar a tabela de junção e as colunas de ligação.

> [!TIP] DICAS:
> - @JoinTable é usada para personalizar o nome da tabela intermediária e suas colunas.
> - O fetch padrão para @ManyToMany é LAZY.

## 2. Chaves Primárias Compostas
- Chave primária formada por mais de um campo.
- Anotações principais:
  - @Embeddable: marca uma classe como incorporável (classe de chave composta);
  - @EmbeddedId: indica que o ID é uma instância de uma classe embutida.
- Exemplo: tabela "Pessoa" com chave primária composta por CPF e RG.
- A classe embutida encapsula os campos da chave composta.
- Ao criar a entidade "Pessoa", usa-se @EmbeddedId para indicar que a classe contém uma chave primária composta.

| ENTIDADE PESSOA | CHAVE PRIMÁRIA COMPOSTA |
|---|---|
| cpf (String) | PK |
| rg (String) | PK |
| nome (String) | - |

> [!CAUTION] OBSERVAÇÃO:
> - A classe que representa a chave composta deve implementar Serializable.
> - Os métodos equals() e hashCode() devem ser sobrescritos para garantir a correta comparação dos objetos.

## 3. Herança e Mapeamento com @MappedSuperclass
- @MappedSuperclass indica que uma classe é uma superclasse mapeada, mas não é uma entidade completa.
- Classes com @MappedSuperclass não são persistidas diretamente no banco de dados.
- Serve como classe base para que outras entidades herdem atributos.
- No mundo relacional, as colunas devem ser definidas em cada tabela individualmente.
- Ao criar entidades que herdam da classe base, elas se tornam tabelas com todos os atributos.
- A classe base em si não se torna uma tabela.
- Exemplo: classes "Usuário" e "Produto" herdam de uma classe base que possui id e data_criacao.
- Cada entidade filha terá seus próprios atributos específicos.

> [!CAUTION] OBSERVAÇÃO:
> - A classe com @MappedSuperclass não pode ser usada em consultas JPA, pois não é uma entidade.
> - Relacionamentos definidos na superclasse são herdados pelas subclasses.

### 3.1 Comparativo entre Tabelas com Herança
| USUÁRIO | PRODUTO |
|---|---|
| BIGINT id (PK) | BIGINT id (PK) |
| TIMESTAMP data_criacao | TIMESTAMP data_criacao |
| VARCHAR nome | VARCHAR nome |
| VARCHAR email | DECIMAL preco |

### 3.2 Exemplo de Código com @MappedSuperclass
```java
@MappedSuperclass
public abstract class Pessoa {
    @Id
    private Long id;
    private String nome;
    @Column(length = 11)
    private String cpf;
}

@Entity(name = "Professor")
public class Professor extends Pessoa {
    private BigDecimal salario;
}

@Entity(name = "Aluno")
public class Aluno extends Pessoa {
    private boolean diurno;
}
```

- Pessoa é uma superclasse mapeada, mas não vira tabela.
- Professor e Aluno herdam id, nome e cpf.
- Professor possui atributo adicional salario.
- Aluno possui atributo adicional diurno.
- A tabela Aluno conterá: id (PK), nome, cpf e diurno.
- A tabela Professor conterá: id (PK), nome, cpf e salario.

> [!TIP] DICAS:
> - @MappedSuperclass é muito útil para centralizar atributos comuns como id, data_criacao, data_atualizacao, etc.
> - A ausência de @NotNull no salario implica que o atributo pode ser nulo.

## 4. Configuração JPA e Hibernate
- Para configurar o Hibernate como provedor de persistência no JPA, utiliza-se a instrução org.hibernate.ejb.HibernatePersistence.
- Essa configuração deve ser colocada no arquivo persistence.xml.
- O arquivo persistence.xml é o arquivo de configuração padrão do JPA.
- Nele são definidas as unidades de persistência (persistence-unit).
- A unidade de persistência contém configurações como:
  - Driver JDBC;
  - URL de conexão;
  - Usuário e senha;
  - Dialeto do banco de dados;
  - Lista de classes (entidades) mapeadas.

> [!CAUTION] OBSERVAÇÃO:
> - O nome do arquivo de configuração JPA é persistence.xml e deve estar localizado no diretório META-INF.

## 5. Consultas com TypedQuery
- O método createNamedQuery() do EntityManager retorna um objeto do tipo TypedQuery.
- TypedQuery é uma interface que representa uma consulta tipada, garantindo que o resultado seja do tipo especificado.
- Exemplo de uso:
  - EntityManager manager = Persistence.createEntityManagerFactory("trtPU").createEntityManager();
  - manager.createNamedQuery("Acesso.findByUserSenha", Acesso.class);
- O retorno é do tipo TypedQuery<Acesso>.
- A consulta tipada oferece maior segurança de tipos e elimina a necessidade de casting.
- Permite também a utilização de parâmetros com métodos como setParameter().

> [!TIP] DICAS:
> - A anotação @NamedQuery é usada para definir consultas JPQL nomeadas na própria entidade.
> - TypedQuery é preferível a Query para evitar erros de casting em tempo de execução.
