# JSF 2

## 1. JSF Facelets

### 1.1 Definição e Contexto
- Facelet é a tecnologia de view padrão para JSF, substituindo o JSP.
- Oferece um sistema de templates baseado em XML para a construção de interfaces de usuário em aplicações JSF.

### 1.2 Vantagens sobre JSP
- Performance: melhor performance por evitar a fase de compilação do JSP para servlets.
  - O JSP continha códigos Java dinâmicos, então o código tinha que ser compilado para assim se tornar um HTML estático.
  - Isso é um problema de performance quando comparado ao JSF.
- Reuso de Código: facilita a reutilização de componentes e a criação de templates, permitindo uma abordagem mais modular.
- Expression Language Aprimorada: suporta o uso extensivo da Expression Language (EL) para vinculação de dados e integração de lógica de backend.

### 1.3 Exemplo de Código Facelets
```html
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml"
      xmlns:h="http://xmlns.jcp.org/jsf/html"
      xmlns:f="http://xmlns.jcp.org/jsf/core">
    <h:head><title>Cadastro de Usuário</title></h:head>
    <h:body>
        <h:form>
            <h:panelGrid columns="3">
                <!-- InputText para Username -->
                <h:outputLabel for="username" value="Username:"/>
                <h:inputText id="username" value="#{userBean.username}" required="true"
                             requiredMessage="O username é obrigatório."/>
                <!-- InputSecret para Password -->
                <h:outputLabel for="password" value="Password:"/>
                <h:inputSecret id="password" value="#{userBean.password}" required="true"
                               redisplay="false" requiredMessage="A senha é obrigatória."/>
                <!-- SelectOneMenu para Versões do Java -->
                <h:outputLabel for="javaVersion" value="Versão do Java:"/>
                <h:selectOneMenu id="javaVersion" value="#{userBean.javaVersion}">
                    <f:selectItem itemValue="8" itemLabel="Java 8"/>
                    <f:selectItem itemValue="9" itemLabel="Java 9"/>
                </h:selectOneMenu>
                <!-- SelectOneRadio para RadioButton -->
                <h:outputLabel value="Preferência de Contato:"/>
                <h:selectOneRadio id="contactPreference" value="#{userBean.contactPreference}">
                    <f:selectItem itemValue="email" itemLabel="Email"/>
                    <f:selectItem itemValue="phone" itemLabel="Telefone"/>
                </h:selectOneRadio>
                <!-- CommandButton para Submissão -->
                <h:commandButton value="Registrar" action="#{userBean.register}"/>
            </h:panelGrid>
        </h:form>
        <h:messages/>
    </h:body>
</html>
```

### 1.4 Exemplo de ManagedBean
```java
@ManagedBean
@RequestScoped
public class UserBean {
    private String username;
    private String password;
    private String javaVersion;
    private String contactPreference;
    
    // Getters e Setters omitidos
    
    // Método chamado ao submeter o formulário
    public String register() {
        Severity severidade = FacesMessage.SEVERITY_INFO;
        String resumo = "Registro bem-sucedido";
        String detalhe = "Usuário " + username + " registrado com sucesso!";
        
        //criando uma mensagem global
        FacesMessage msg = new FacesMessage(severidade, resumo, detalhe);
        FacesContext.getCurrentInstance().addMessage(null, msg);
        
        // Retorna null para permanecer na mesma página
        return null;
    }
}
```

> [!TIP] DICAS:
> - O campo de ID fica null para que possa ser preenchido, se não, deixa de ser uma mensagem global.
> - Deve-se usar o Input Text e o Input Secret.

> [!CAUTION] OBSERVAÇÃO:
> - O output label não deve ser seguido diretamente por outro output label; deve ser seguido por um input text.

## 2. JSF Expression Language (EL)

### 2.1 Sintaxe da EL
- A Expression Language é utilizada para vinculação de dados entre a view e os managed beans.
- A sintaxe correta é: `#{pessoa.nome}`.
- Permite acessar propriedades de beans e invocar métodos.

### 2.2 Exemplo de Uso
- Para obter uma instância de Pessoa e chamar o método getNome: `#{pessoa.nome}`.

## 3. Ciclo de Vida do JSF

### 3.1 Fases do Ciclo de Vida (RAPIAR)
| FASE | DESCRIÇÃO |
|---|---|
| Restore View | O JSF constrói ou restaura a árvore de componentes da UI para a página solicitada. Se é a primeira vez que a página é acessada, uma nova árvore é construída. Se é um postback, a árvore existente é restaurada. |
| Apply Request Values | Cada componente da UI na árvore de componentes processa os dados recebidos da requisição, convertendo-os e validando-os conforme necessário. |
| Process Validations | São executadas as validações nos dados de entrada. Se algum dado não passar na validação, a fase de resposta é chamada diretamente, e o processo de atualização do modelo e invocação de aplicativo é ignorado. |
| Update Model Values | Os valores validados são transferidos para as propriedades dos beans correspondentes, atualizando o modelo de dados da aplicação. |
| Invoke Application | O JSF invoca a lógica de aplicativo, como a chamada de métodos de ação em managed beans, que podem resultar em navegação para outra página. |
| Render Response | Na última fase, o JSF gera a resposta HTML a ser enviada de volta ao cliente, renderizando a árvore de componentes da UI para HTML. |

### 3.2 Mnemônico RAPIAR
- Restaura, Aplica, Processa, Atualiza, Invoca, Renderiza.

> [!TIP] DICAS:
> - Árvore é a primeira fase: Restore View.

> [!CAUTION] OBSERVAÇÃO:
> - A fase em que se atualizam valores do modelo só é alcançada após todos os componentes JSF serem considerados válidos na fase que processa as validações.
> - Se algum dado não é aprovado na validação, a fase de resposta é chamada diretamente.

## 4. Escopos no JSF

### 4.1 Escopos JSF 2.2 ou Inferior
| ESCOPO | DESCRIÇÃO |
|---|---|
| @RequestScoped | Duração da requisição HTTP. |
| @SessionScoped | Duração da sessão HTTP do usuário. |
| @ApplicationScoped | Compartilhado durante a vida útil da aplicação web. |
| @ViewScoped | Persiste durante a visualização de uma página JSF. |
| @NoneScoped | Bean não gerenciado, sem ciclo de vida. |
| @CustomScoped | Permite definir um ciclo de vida personalizado. |

### 4.2 Escopos CDI
| ESCOPO | DESCRIÇÃO |
|---|---|
| @RequestScoped | Similar ao JSF, com integração em várias tecnologias. |
| @SessionScoped | Similar ao JSF, duração da sessão HTTP. |
| @ApplicationScoped | Similar ao JSF, compartilhado por toda a aplicação. |
| @Dependent | O escopo padrão, a duração depende do bean consumidor. |
| @ConversationScoped | Mantém o estado em uma série de interações. |
| @Transactional | Gerenciamento do bean dentro de uma transação JTA. |

### 4.3 Resumo dos Escopos por Duração
- RequestScoped: o estado do bean persiste apenas por uma única requisição HTTP.
- SessionScoped: o estado do bean persiste por múltiplas requisições HTTP provenientes de um mesmo usuário.
- ApplicationScoped: o estado do bean persiste por todo o tempo de vida da aplicação WEB.

> [!TIP] DICAS:
> - @SessionScoped: o estado do bean persiste por múltiplas requisições HTTP provenientes de um mesmo usuário.
> - @ApplicationScoped: o estado do bean persiste por todo o tempo de vida da aplicação WEB.
> - @RequestScoped: o estado do bean persiste apenas por uma única requisição HTTP.

### 4.4 Relação entre Escopos e Injeção de Dependência
- Para uma aplicação JSF usar um bean que injeta outra classe bean, o primeiro bean precisa ser capaz de manter seu estado por um certo tempo, que será especificado em sua anotação de escopo.
