# Ferramenta de Versionamento Git 2

## 1. Características do Sistema
- O Git é um sistema de controle de versão distribuído onde cada cópia do repositório contém todo o histórico de alterações.
- Proporciona alta resiliência a falhas e permite que o desenvolvedor realize o trabalho em modo offline.
- Apresenta alta velocidade e desempenho no gerenciamento de grandes volumes de código-fonte.
- Funciona como um software de código aberto com uma comunidade ativa que contribui para o seu aprimoramento constante.
- Possui recursos de segurança voltados para autenticação e autorização para proteger o acesso e a integridade dos dados.

## 2. Rastreamento e Histórico de Revisões
- Realiza o rastreamento de todas as mudanças feitas em arquivos e diretórios permitindo identificar o autor e o momento da alteração.
- Mantém uma linha do tempo completa e rastreável de todas as modificações ocorridas durante o projeto.
- Permite a recuperação de versões anteriores do código e a reconstrução total do software através do uso de tags.
- Capacidade de controlar versões de qualquer tipo de arquivo, incluindo documentos, imagens e dados, embora tenha sido projetado para código-fonte.

## 3. Ramificação e Colaboração em Equipe
- Facilita a criação de ramificações (branches) independentes para permitir o desenvolvimento paralelo de funcionalidades.
- Oferece suporte para a fusão (merge) dessas ramificações de volta ao ramo principal, comumente chamado de master ou main.
- Gerencia conflitos de maneira controlada quando múltiplos desenvolvedores realizam alterações simultâneas no mesmo arquivo.
- Permite o uso da web para facilitar a atuação de equipes remotas em diferentes localidades.
- Integra-se com plataformas de hospedagem como GitHub, GitLab e Bitbucket para facilitar a colaboração e processos de CI/CD.
- Suporta o rastreamento de submódulos para inclusão de repositórios externos ou bibliotecas de terceiros no projeto.

## 4. Tabela de Comandos do Git
| COMANDO | DESCRIÇÃO |
|---|---|
| git init | Inicializa um novo repositório no diretório atual |
| git clone | Clona um repositório remoto para o computador local |
| git add | Adiciona arquivos específicos para o índice de preparação |
| git add . | Adiciona todos os arquivos modificados ao índice de preparação |
| git commit -m | Cria um registro das alterações com uma mensagem descritiva |
| git status | Mostra o estado atual do repositório e arquivos modificados |
| git log | Exibe todo o histórico de registros do repositório |
| git diff | Mostra as diferenças entre arquivos e o último registro |
| git branch | Lista as ramificações locais ou cria uma nova ramificação |
| git checkout | Muda para uma ramificação específica do projeto |
| git merge | Mescla a ramificação especificada com a ramificação atual |
| git pull | Atualiza o repositório local com mudanças do remoto |
| git push | Envia as mudanças do repositório local para o remoto |
| git fetch | Baixa as atualizações do remoto sem realizar a mesclagem |
| git reset | Remove o arquivo da área de preparação mantendo as mudanças |
| git revert | Reverte um registro específico criando um novo registro |
| git stash | Armazena mudanças temporariamente para limpar o diretório |
| git tag | Cria uma marcação ou etiqueta no registro atual |

> [!TIP] DICAS: 
> - O conhecimento da linha de comando é exigido em provas de concurso, pois geralmente não há opção de interagir por interfaces gráficas.
> - Praticar com a ferramenta ajuda na eliminação de opções incorretas em questões de múltipla escolha sobre o funcionamento do versionamento.

> [!CAUTION] OBSERVAÇÃO: 
> - O Git foi criado por Linus Torvalds em 2005 após os desenvolvedores do kernel Linux optarem por não usar mais o software BitKeeper.
> - Um equívoco comum é executar comandos apenas no repositório local sem realizar o envio posterior para o repositório remoto.
> - Em uma organização clássica, a ramificação master é reservada para o código pronto para produção e acionamento de pipelines.
