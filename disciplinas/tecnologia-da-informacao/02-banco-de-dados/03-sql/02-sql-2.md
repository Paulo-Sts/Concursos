# Banco de Dados - Linguagem SQL 2

## 1. Estrutura da Tabela Produto
- O exemplo utiliza uma tabela com os seguintes campos: Nome, Categoria, Preço e Unidade.
- Tabela de exemplo:
  | NOME | CATEGORIA | PRECO | UNIDADE |
  |------|-----------|-------|---------|
  | Café | Mercearia | R$ 8,99 | KG |
  | Açúcar | Mercearia | R$ 10,20 | 5 KG |
  | Sabão em Pó | Limpeza | R$ 9,90 | KG |
  | Vinho | Bebida | R$ 59,90 | 750 ML |
  | Refrigerante | Bebida | R$ 7,90 | 2 L |

## 2. Comando SELECT e Filtros com WHERE
- O comando SELECT permite selecionar colunas específicas ou todas as colunas (*).
- A cláusula WHERE filtra os registros retornados com base em uma condição.
- Exemplo: selecionar nome e preço apenas das bebidas.
  ```sql
  SELECT Nome, Preco FROM produto WHERE Categoria = 'Bebida';
  ```
- Resultado:
  | NOME | PRECO |
  |------|-------|
  | Vinho | R$ 59,90 |
  | Refrigerante | R$ 7,90 |
- Ao utilizar SELECT *, todas as colunas são trazidas.
- Exemplo: filtrar produtos com preço maior que 10.
  ```sql
  SELECT * FROM produto WHERE Preco > 10;
  ```
- Resultado:
  | NOME | CATEGORIA | PRECO | UNIDADE |
  |------|-----------|-------|---------|
  | Açúcar | Mercearia | R$ 10,20 | 5 KG |
  | Vinho | Bebida | R$ 59,90 | 750 ML |

## 3. Ordenação com ORDER BY
- O comando ORDER BY ordena os resultados de acordo com uma coluna especificada.
- A ordenação padrão é crescente (ASC), mas pode ser definida como decrescente (DESC).
- Exemplo: colocar todos os produtos em ordem alfabética pelo nome.
  ```sql
  SELECT * FROM produto ORDER BY Nome;
  ```
- Resultado:
  | NOME | CATEGORIA | PRECO | UNIDADE |
  |------|-----------|-------|---------|
  | Açúcar | Mercearia | R$ 10,20 | 5 KG |
  | Café | Mercearia | R$ 8,99 | KG |
  | Refrigerante | Bebida | R$ 7,90 | 2 L |
  | Sabão em Pó | Limpeza | R$ 9,90 | KG |
  | Vinho | Bebida | R$ 59,90 | 750 ML |

## 4. Remoção de Duplicatas com DISTINCT
- O comando DISTINCT remove todas as repetições (linhas duplicadas) do resultado.
- Exemplo: listar todas as categorias sem repetição.
  ```sql
  SELECT DISTINCT Categoria FROM produto;
  ```
- Retorna: Mercearia, Limpeza, Bebida.
- É possível combinar DISTINCT com ORDER BY para ordenar o resultado.
  ```sql
  SELECT DISTINCT Categoria FROM produto ORDER BY Categoria;
  ```

> [!TIP] DICAS: 
> - Em provas, o DISTINCT é muito utilizado para confundir o candidato. Ele elimina duplicatas, mas não altera a ordenação a menos que combinado com ORDER BY.

## 5. Filtros com LIKE
- O operador LIKE é utilizado para buscar padrões em strings.
- Caracteres curinga:
  - %: representa qualquer sequência de caracteres.
  - _: representa um único caractere.
- Exemplo: selecionar produtos cujo nome contenha a letra "a".
  ```sql
  SELECT * FROM produto WHERE Nome LIKE '%a%';
  ```

> [!CAUTION] OBSERVAÇÃO: 
> - O LIKE diferencia maiúsculas de minúsculas dependendo da configuração do banco de dados. Em alguns SGBDs, é necessário utilizar funções como UPPER() para garantir a correspondência.

## 6. Operadores Lógicos: AND e OR
- AND: exige que todas as condições sejam verdadeiras para que o resultado seja verdadeiro.
  - Se uma condição for falsa, o resultado é falso.
- OR: exige que pelo menos uma das condições seja verdadeira.
  - Se todas forem falsas, o resultado é falso.
- Exemplo de uso combinado:
  ```sql
  SELECT * FROM produto WHERE Categoria = 'Bebida' AND Preco > 10;
  ```

> [!CAUTION] OBSERVAÇÃO: 
> - O operador NOT pode ser utilizado para inverter uma condição, como NOT LIKE ou NOT IN.

## 7. Operador IN
- O operador IN verifica se um valor pertence a um conjunto de valores.
- É mais eficiente do que encadear múltiplas condições com OR.
- Exemplo: selecionar produtos das categorias "Bebida" ou "Limpeza".
  ```sql
  SELECT * FROM produto WHERE Categoria IN ('Bebida', 'Limpeza');
  ```
- O comando NOT IN seleciona os registros que não pertencem ao conjunto.
  ```sql
  SELECT * FROM produto WHERE Categoria NOT IN ('Bebida', 'Limpeza');
  ```

## 8. Subconsultas
- Subconsulta é uma consulta dentro de outra consulta.
- A consulta mais interna é executada primeiro, e seu resultado é usado pela consulta externa.
- Exemplo prático: selecionar produtos cuja categoria tenha ID 20 (limpeza) ou 30 (bebida).
  - Primeiro, obtém-se os IDs das categorias desejadas:
    ```sql
    SELECT ID FROM categoria WHERE Nome IN ('Bebida', 'Limpeza');
    ```
  - Depois, utiliza-se esses IDs na consulta principal:
    ```sql
    SELECT Nome, Preco FROM produto WHERE Categoria_ID IN (20, 30);
    ```
- A subconsulta retorna apenas os valores de ID, e a consulta principal compara esses dados com os produtos cadastrados.

> [!CAUTION] OBSERVAÇÃO: 
> - Em concursos como os da FGV, podem ser cobradas subconsultas com até três níveis de aninhamento. A resolução deve começar pela consulta mais interna.

## 9. Normalização e Integridade Referencial
- Em uma base de dados não normalizada, há repetição de valores (ex.: categoria "Mercearia" aparece várias vezes).
- Problemas da não normalização:
  - Redundância;
  - Ocupação desnecessária de espaço;
  - Inconsistências (ex.: grafias diferentes para a mesma categoria).
- Solução: utilizar tabelas de referência (ex.: tabela Categoria com chave primária única).
- Os produtos devem conter uma chave estrangeira (ForeignKey) que referencie a tabela de categorias.
- Vantagens:
  - Integridade referencial garantida;
  - Não é possível alterar ou excluir uma categoria se houver produtos dependentes;
  - Redução de redundância.

## 10. Tratamento de Valores Nulos (NULL)
- NULL representa ausência de informação.
- Não é possível comparar NULL com operadores como = ou !=.
- Exemplo incorreto: `WHERE campo = NULL` → não funciona.
- Correto: utilizar `IS NULL` ou `IS NOT NULL`.
  ```sql
  SELECT * FROM produto WHERE Categoria_ID IS NULL;
  ```

> [!CAUTION] OBSERVAÇÃO: 
> - Em provas, o uso incorreto de `= NULL` é uma pegadinha comum e resulta em falha na consulta.

## 11. Operadores de Comparação
- = (igual);
- < (menor que);
- <= (menor ou igual);
- > (maior que);
- >= (maior ou igual);
- != ou <> (diferente).

## 12. Boas Práticas e Recomendações para Provas
- Testar diferentes combinações de comandos: WHERE, ORDER BY, DISTINCT, LIKE, IN, BETWEEN.
- BETWEEN: utilizado para filtrar valores dentro de um intervalo (inclusive os extremos).
  ```sql
  SELECT * FROM produto WHERE Preco BETWEEN 10 AND 50;
  ```
- Comandos de agregação (COUNT, SUM, AVG, MAX, MIN) são cobrados em provas e serão abordados em módulos posteriores.
- Em ambientes reais de SGBD, qualquer erro de sintaxe ou nome de coluna impede a execução.
- Para provas, é fundamental reconhecer padrões de consulta e aplicar a lógica corretamente.

> [!TIP] DICAS: 
> - O SQL é amplamente cobrado em concursos, mesmo quando não mencionado explicitamente no edital.
> - Saber executar comandos SQL permite consultas mais ágeis e precisas do que manipular dados em planilhas, especialmente em grandes volumes.
