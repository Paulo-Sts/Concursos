# Extreme Programming 2

## 1. Jogo do Planejamento
- O jogo do planejamento utiliza os cartões de estória como as principais entradas para o processo.
- A equipe de desenvolvimento divide os itens em tarefas específicas para estimar o esforço e os recursos necessários.
- O processo exige a colaboração constante entre o cliente e os desenvolvedores para o refinamento e a priorização dos requisitos.
- O cliente possui a responsabilidade de escolher as funcionalidades que oferecem suporte imediato aos negócios para implementação prioritária.

## 2. Requisitos e o Conceito de Spyke
- A intenção do método é identificar funcionalidades úteis que possam ser implementadas em ciclos de aproximadamente duas semanas.
- Spyke ⟶ incremento no qual nenhuma programação de funcionalidade é realizada, servindo para explorar soluções ou compreender problemas complexos;
- Pode ser utilizado para a criação de protótipos, projeto da arquitetura ou desenvolvimento da documentação do sistema;
- Funciona como uma prova de conceito para validar o entendimento da equipe sobre uma determinada estória de usuário.

> [!TIP] DICAS: 
> - O planejamento (planning game) não é feito isoladamente pelo cliente; ele ocorre obrigatoriamente em colaboração com os desenvolvedores.
> - O valor da estória de usuário deve ser compreendido no planejamento para garantir que o software seja útil logo após sua disponibilização.

## 3. Características do Processo XP
- O XP é caracterizado como um processo iterativo e incremental que enfatiza a agregação de valor desde o início.
- Novas versões do software são construídas várias vezes ao dia para garantir a integração constante.
- Existe um comprometimento rigoroso com os prazos de releases, que são entregues aos clientes a cada duas semanas.
- Caso ocorram problemas no desenvolvimento, funcionalidades planejadas podem ser removidas após consulta ao cliente, que integra a equipe.
- A refatoração é uma prática fundamental para permitir a adição contínua de novas funcionalidades ao sistema.

## 4. Estratégia de Testes no XP
- A validação do sistema é centralizada na prática crucial de pensar e escrever o teste antes da implementação do código.
- Os critérios de testes e aceitação podem ser executados de forma manual ou automatizada através de frameworks específicos.

| CARACTERÍSTICA DE TESTE | DESCRIÇÃO |
|---|---|
| Desenvolvimento test-first | Prática conhecida como tdd onde o teste precede o código |
| Desenvolvimento incremental | Testes criados a partir de cenários de uso |
| Envolvimento do usuário | Prática de atdd para validação e desenvolvimento de testes |
| Frameworks automatizados | Uso de ferramentas para garantir a execução contínua dos testes |

## 5. Escalonamento e Versão Industrial
- Embora concebidos inicialmente para times pequenos, os métodos ágeis admitem adaptações para equipes de maior porte.
- A variante industrial do XP inclui elementos como avaliação imediata, comunidade de projeto e mapeamento do projeto.
- O gerenciamento orientado a testes e a realização de retrospectivas são pilares para a aprendizagem contínua da equipe.

> [!CAUTION] OBSERVAÇÃO: 
> - No spyke, o foco é exclusivamente o aprendizado e a exploração técnica, por isso não há produção de código final.
> - A remoção de funcionalidades para cumprir prazos de release é uma regra de compromisso que só deve ocorrer após a devida consulta ao cliente.
