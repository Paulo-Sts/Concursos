# Ferramenta de Versionamento Git 3

## 1. Configuração da Ferramenta
- O comando git config é utilizado para ler e alterar as configurações do Git em níveis de repositório, pessoal ou de sistema.
- git --version ⟶ comando utilizado para verificar se a ferramenta foi instalada corretamente no sistema.
- git config --global user.name ⟶ configura o nome do usuário que será vinculado a todas as transações de registro de alterações.
- git config --global user.email ⟶ define o endereço de correio eletrônico que será associado aos registros de versão do desenvolvedor.

## 2. Criação e Download de Repositórios
- git init ⟶ inicia um novo repositório local e cria uma pasta oculta chamada .git para monitorar as alterações no diretório.
- Ao executar o comando git init em um diretório vazio, a ferramenta cria toda a estrutura necessária para o controle de versionamento.
- git clone ⟶ realiza o download de um projeto completo, incluindo todo o seu histórico de versões, de um repositório remoto para o ambiente local.

## 3. Áreas de Trabalho e Ciclo de Vida
- O Git opera com uma estrutura de árvore organizada em três níveis fundamentais: diretório de trabalho, área de preparação e cabeçalho.
- Diretório de Trabalho (Working Directory) ⟶ área onde o usuário cria, edita e modifica ativamente os arquivos do projeto.
- Área de Preparação (Staging Area ou Index) ⟶ local intermediário onde as alterações são organizadas e selecionadas antes de serem registradas.
- Repositório (Head ou History) ⟶ local onde os registros de alterações (commits) e todas as versões do projeto são armazenados permanentemente.

## 4. Gerenciamento e Estados dos Arquivos
- Arquivos Não Rastreados (Untracked) ⟶ arquivos presentes no diretório de trabalho que ainda não foram adicionados ao controle do Git.
- Arquivos Rastreados (Tracked) ⟶ arquivos conhecidos pela ferramenta que podem estar nos estados não modificado, modificado ou preparado.
- Arquivos Preparados (Staged) ⟶ arquivos que já foram movidos para a área intermediária e estão prontos para o próximo registro no repositório.

## 5. Tabela de Instruções e Comandos
| COMANDO | DESCRIÇÃO DA AÇÃO | DETALHE TÉCNICO |
|---|---|---|
| git add [arquivo] | Adiciona um arquivo específico ao index | Realiza o snapshot para a preparação |
| git add . | Adiciona todas as mudanças ao index | Utilizado para preparar todos os arquivos |
| git commit | Grava as alterações no histórico local | Registra o estado atual da staging area |
| git commit -m | Registra alterações com mensagem | Opção para descrever a modificação feita |
| git commit -a | Prepara e registra automaticamente | Ignora a etapa manual da staging area |
| git status | Lista arquivos novos ou modificados | Exibe o estado dos rastreios e registros |
| git reset | Desfaz registros e remove do stage | Pode reverter a ação do comando git add |
| git checkout | Copia arquivos do stage para o diretório | Utilizado para descartar alterações locais |
| git diff | Exibe diferenças nos arquivos | Mostra mudanças que não foram preparadas |
| git log | Exibe o histórico de registros | Lista os commits feitos no branch atual |
| git show | Mostra detalhes de objetos do Git | Exibe metadados de commits, tags e árvores |

> [!TIP] DICAS: 
> - A prática frequente com a ferramenta de linha de comando é recomendada para facilitar a resolução de questões técnicas em provas.
> - O uso do comando git status permite ao usuário identificar rapidamente quais arquivos estão prontos para o registro ou ainda não rastreados.

> [!CAUTION] OBSERVAÇÃO: 
> - Bancas examinadoras como FGV e Cebraspe costumam cobrar comandos e fluxos do Git sempre que o tema consta no edital.
> - O comando git reset [commit] preserva mudanças locais, enquanto o git reset --hard descarta todo o histórico até o ponto especificado.
> - Se as alterações já tiverem sido enviadas ao servidor remoto através de um push, o comando reset não funcionará corretamente, devendo-se usar o comando reverse.
