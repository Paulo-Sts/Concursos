# Persistência com JPA e Hibernate 3

## 1. Hibernate
- O Hibernate é um framework de mapeamento objeto-relacional (ORM) para Java que simplifica o desenvolvimento de aplicações que interagem com bancos de dados relacionais.
- O Hibernate é responsável por resolver o problema da tradução entre o mundo relacional e o mundo orientado a objetos.
- O mapeamento de tabelas para um ambiente orientado a objetos apresenta diversos desafios, como a questão da herança.
- Enquanto em um banco de dados relacional as tabelas não têm herança, no Java é possível estabelecer hierarquias de classes.
- Para que isso funcione, é necessário utilizar anotações e recursos específicos, o que resulta na criação de tabelas que refletem essas hierarquias no banco de dados.
- O Hibernate implementa a especificação JPA (Java Persistence API) e oferece funcionalidades adicionais.
- Seu principal objetivo é abstrair o acesso ao banco de dados, permitindo que desenvolvedores trabalhem com objetos Java, em vez de interagirem diretamente com SQL.
- A interação com o Hibernate ocorre por meio do padrão SessionFactory, que é responsável por criar instâncias de sessão para gerenciar as entidades e realizar operações de persistência.
- Essa abordagem simplifica o gerenciamento de entidades e as operações relacionadas ao banco de dados.

### 1.1 Arquitetura do Hibernate
- O Hibernate não se incorpora ao banco de dados relacional, mas se encontra entre a camada de acesso a dados do aplicativo Java e o banco de dados relacional.
- O Hibernate atua como uma interface entre a API JPA e o banco de dados relacional, facilitando a comunicação entre os dois e possibilitando a execução de comandos SQL de forma eficiente.

| HIERARQUIA DA CAMADA DE ACESSO A DADOS |
|---|
| Data Access Layer |
| Java Persistence API |
| Hibernate Native API |
| JDBC |
| Relational Database |

> [!TIP] DICAS:
> - O Hibernate fica entre a camada de acesso a dados e o banco de dados relacional, não dentro do banco.
> - O Hibernate implementa a JPA, mas possui funcionalidades nativas próprias.

### 1.2 Exemplo de Configuração do Hibernate
- Para configurar o Hibernate e criar a SessionFactory, utiliza-se o arquivo `hibernate.cfg.xml` ou o `persistence.xml`.
- No exemplo abaixo, é ilustrada a parte de configuração e criação da SessionFactory:

```java
public class HibernateExemplo {
    public static void main(String[] args) {
        // 1. Configurar o Hibernate e criar a SessionFactory
        SessionFactory sessionFactory = new Configuration()
                .configure("hibernate.cfg.xml")
                .buildSessionFactory();

        // 2. Obter uma Sessão
        Session session = sessionFactory.openSession();

        // 3. Iniciar uma Transação
        Transaction tx = session.beginTransaction();

        // 4. Criar uma Instância da Entidade
        Pessoa pessoa = new Pessoa("Maria");

        // 5. Operação de Persistência: salvar a entidade
        session.save(pessoa);

        // 6. Commit da Transação
        tx.commit();

        // 7. Fechar a Sessão e a SessionFactory
        session.close();
        sessionFactory.close();
    }
}
```

- Observa-se que o JPA foi influenciado pelo Hibernate, que antecede o JPA. O JPA incorporou elementos do Hibernate, mas também introduziu padrões próprios.
- No Hibernate, existem duas opções de configuração: o `persistence.xml` e o `hibernate.cfg.xml`.
- Este último, o `hibernate.cfg.xml`, é um exemplo de configuração e sua estrutura é bastante similar ao `persistence.xml`.
- No `hibernate.cfg.xml`, é necessário definir o driver do banco de dados, além da string de conexão, como usuário, senha e o dialeto do banco, que neste caso é o H2, um banco de dados em memória.
- A utilização do H2 facilita o desenvolvimento, permitindo feedback rápido sem a necessidade de um banco de dados pesado.
- Há configurações específicas que podem ser discutidas, incluindo a definição da classe utilizada, que pode ser simplificada com o uso de anotações que eliminam a necessidade de arquivos XML.
- A configuração inicial começa com o arquivo `cfg.xml`, a partir do qual se constrói a SessionFactory. Com a sessão aberta, é possível iniciar uma transação.

### 1.3 Exemplo de Arquivo hibernate.cfg.xml
- A estrutura do `hibernate.cfg.xml` define as propriedades de conexão, dialeto e mapeamento das classes:

```xml
<?xml version='1.0' encoding='utf-8'?>
<!DOCTYPE hibernate-configuration SYSTEM
"http://hibernate.org/dtd/hibernate-configuration-3.0.dtd">
<hibernate-configuration>
    <session-factory>
        <property name="hibernate.connection.driver_class">org.h2.Driver</property>
        <property name="hibernate.connection.url">jdbc:h2://test</property>
        <property name="hibernate.connection.username">sa</property>
        <property name="hibernate.connection.password"></property>

        <property name="hibernate.dialect">org.hibernate.dialect.H2Dialect</property>
        <property name="hibernate.show_sql">true</property>
        <property name="hibernate.format_sql">true</property>

        <property name="hibernate.hbm2ddl.auto">update</property>
        <mapping class="com.example.model.Pessoa"/>
    </session-factory>
</hibernate-configuration>
```

> [!CAUTION] OBSERVAÇÃO:
> - No Java, o SQL é gerado em tempo de execução, não em tempo de compilação.
> - No Hibernate, é possível trabalhar diretamente com os objetos sem a necessidade de escrever código HQL.

## 2. HQL (Hibernate Query Language)
- O JPQL (Java Persistence Query Language) é similar ao HQL, com o JPQL sendo quase que completamente inspirado no HQL.
- O HQL permite realizar consultas baseadas em entidades, ao invés de tabelas, e oferece suporte a extensões específicas do Hibernate.

```java
String hql = "FROM Estudante WHERE nome = :nome";
Query query = session.createQuery(hql);
query.setParameter("nome", "João");
List resultados = query.list();
```

## 3. Ciclo de Vida do Hibernate
- Os estados do ciclo de vida do objeto podem ser classificados como: transient, persistent e detached.
- A identificação correta desses estados é importante, pois várias questões podem ser facilmente respondidas com esse conhecimento.

### 3.1 Exemplo de Ciclo de Vida
- No exemplo abaixo, é possível entender o ciclo de vida do Hibernate:

```java
Estudante estudante = new Estudante();
estudante.setNome("João"); // Objeto em estado Transient

Session session = sessionFactory.openSession();
Transaction tx = session.beginTransaction();
session.save(estudante); // Agora, 'estudante' está em estado Persistent

tx.commit();
session.close();
// A sessão foi fechada, 'estudante' está em estado Detached
```

### 3.2 Estados do Ciclo de Vida
- Transient:
  - O objeto está instanciado com a palavra `new`.
  - Não está associado a nenhuma sessão do Hibernate.
  - Não existe no banco de dados.
- Persistent:
  - O objeto está associado a uma sessão ativa do Hibernate.
  - Representa uma linha no banco de dados.
  - Está sincronizado com o banco em operações de flush ou commit.
  - Qualquer alteração nas propriedades do objeto será refletida no banco de dados.
- Detached:
  - O objeto foi persistente, mas está desassociado de qualquer sessão.
  - A sessão foi fechada ou o objeto foi removido (evict).
  - Representa uma linha no banco, mas não está sendo gerenciado.
  - Não há sincronização entre o objeto e a tabela no banco de dados.

### 3.3 Gerenciamento dos Estados
- Para que um objeto seja persistido diretamente em um banco de dados, é necessário criar uma sessão de transação.
- A sessão pode ser iniciada utilizando o comando `beginTransaction()`.
- Se houver a necessidade de evitar que as mudanças no objeto sejam refletidas no banco de dados, é necessário retirar o objeto da sessão do Hibernate.
- Isso pode ser feito comentando a transação e fechando a sessão. Com a sessão encerrada, o objeto muda para o estado "detached".

> [!TIP] DICAS:
> - Transient: objeto criado com `new`, sem sessão e sem registro no banco.
> - Persistent: objeto gerenciado por uma sessão ativa, sincronizado com o banco.
> - Detached: objeto que já foi persistente, mas perdeu a referência da sessão.

> [!CAUTION] OBSERVAÇÃO:
> - No estado Detached, o objeto continua a existir no banco de dados, mas não haverá sincronização entre o objeto e a tabela no banco de dados.

## 4. Anotações do Hibernate
- As anotações são utilizadas para mapear as classes e seus atributos ao banco de dados.

### 4.1 Principais Anotações
- `@Entity`: Utilizada para anotar classes persistentes.
- `@Table`: Utilizada quando o nome da tabela é diferente do nome da entidade.
- `@Id`: Anota atributos que representam chaves primárias, cujos valores podem ser gerados automaticamente.
- `@JoinColumn`: Utilizada para especificar o nome da coluna que define a chave estrangeira relacionada com uma associação "muitos para um" (Many To One).
- `@ManyToOne`: Utilizada para definir o relacionamento muitos para um.

> [!TIP] DICAS:
> - `@Entity`: utilizada em classes persistentes.
> - `@Table`: utilizada quando o nome da tabela difere do nome da entidade.
> - `@Id`: utilizada para chaves primárias, podendo ser geradas automaticamente.
> - `@JoinColumn`: utilizada para especificar a coluna de chave estrangeira em relacionamentos `@ManyToOne`.

> [!CAUTION] OBSERVAÇÃO:
> - A anotação `@TableKey` não existe; a anotação correta para chave primária é `@Id`.
> - A anotação para chave primária no Hibernate é `@Id`, e não `@PrimaryKey`, `@PrymaryId`, `@SpecialKey` ou `@PK`.

## 5. Hibernate Envers
- O Hibernate Envers é uma extensão do Hibernate que permite a auditoria automática de entidades JPA.
- Ele armazena um histórico de mudanças realizadas em entidades, permitindo rastrear modificações em atributos e ações feitas sobre os objetos persistidos.
- É parte integrante da arquitetura técnica do PDPJ-BR, que facilita a auditoria de dados em sistemas corporativos e mantém um registro histórico das alterações para rastreamento.

### 5.1 Exemplo de Auditoria com Hibernate Envers
- Para habilitar a auditoria em uma entidade, utiliza-se a anotação `@Audited`:

```java
@Entity
@Audited // habilita a auditoria para esta entidade
public class Produto {
    @Id private Long id;
    private String nome;
    private BigDecimal preco;
}
```

> [!TIP] DICAS:
> - `@Audited`: anotação utilizada para habilitar a auditoria automática em uma entidade.
> - O Hibernate Envers mantém um histórico de alterações para rastreamento e auditoria.

> [!CAUTION] OBSERVAÇÃO:
> - O Hibernate Envers faz a auditoria das tabelas do Hibernate, e não o gerenciamento de identidade ou single sign-on.
> - O gerenciamento de identidade e acesso com single sign-on é feito pelo Keycloak.
